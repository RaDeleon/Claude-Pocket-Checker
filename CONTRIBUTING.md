# Contributing

Open an issue describing the problem before a large change. Keep pull requests focused and include reproduction steps and relevant test output.

Use synthetic fixtures. Do not upload real conversations, exports, account identifiers, logs with prompt text, credentials or screenshots of private chats. Keep token estimates, hypothetical API pricing and observed account-wide quota readings clearly distinguished.

Do not add remote code, telemetry, a model API call or automatic model selection without an explicit design discussion. Document accessibility/DOM compatibility and update the privacy documentation when stored fields or permissions change.

Run the commands in the README before opening a pull request. Local development records under `_devlog/` are private and must remain ignored.
